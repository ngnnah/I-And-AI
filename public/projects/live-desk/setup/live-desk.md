# Live desk

- The main session writes every reply to its live desk: a markdown file in a month folder of `~/claude-replies/`, one per session, at `<YYYY-MM>/<DD>-<repo>-<topic>.md` (`2026-10/29-my-repo-proj-142-export-retries.md`), where `<DD>` is the two-digit day, `<repo>` is the repo's folder name, and the kebab-case topic starts with the ticket id when the work has one. A desk stays in the month it started. Subagents don't. I read and answer it in Obsidian. A session resumed from a handoff (below) continues its predecessor's file instead of starting one, unless that Handoff moved to a fresh desk.
- Create the session's file on its first turn, before other tool work, with a Status whose Now says what you're starting on. If I installed the desk script (`~/.claude/bin/desk`), `~/.claude/bin/desk new <topic>` (with `--now "<text>"` for the first Now) creates it from the skeleton in this month's folder, opens it and prints its path; call `desk` by that path, which my allow rule matches. Don't hold it back until you have an answer; with focus view on, the file is my only sign the session is working.
- On a session's first turn, show its desk in Obsidian once. With the desk script, `desk new` does it for a new desk; a session that continues a desk (resumed from a handoff, or told to use one) runs `~/.claude/bin/desk open <file>` right after its first `desk check`. Both switch to the desk's tab if one is open, else open it in a new tab, and never load it into the tab in front, which may be another session's desk; so never use `open -a Obsidian <file>` or a bare `obsidian://open`, which do. Switching tabs needs Obsidian's command line interface (Settings → General → Advanced); without it, a desk already in a tab stays where it is and `desk open` says so. Without the script, open a new desk with `open "obsidian://open?vault=<vault name>&file=<path inside the vault, URL-encoded>&paneType=tab"`. That opens a new tab and never loads the desk into the tab in front. It can't switch to a tab that's already open; that needs `desk open` plus Obsidian's CLI, so leave a continued desk where it is.
- The file has two parts, and they are its only H2 headings. At the top, `## Status · updated <MM-DD HH:MM>`, which you rewrite in place so it is always current. Below it, `## Log`: add each reply as a new entry at the bottom, `### @<n> · <MM-DD HH:MM> · <short title>`, with any headings inside an entry at `####`. Only headings use `@<n>`, so a search for `@<n> ` (with the space) lands on the entry; everywhere else, Status, the resume line and answer tags included, an entry is `§<n>`. Never rewrite or reorder log entries, except to tag my answers (below).
- Status has, in this order: `### Now` (a recap of where things stand in two to four lines: what's done, what's under way, whose move it is); `### Immediate actions` (what's due now, mine and yours, my questions to you included); `### Later` (the rest of the plan, mine and yours); `### Decisions` (one line each: the decision, why, who made it, its log entry); `### Done` (one line each, newest first, with its log entry). It holds only what's true now: drop finished items, move answered questions into Decisions, and rewrite a decision's line when it lands or changes (no "Proposed" left on something shipped). Status gets rewritten, so its items have no stable numbers: anywhere in the file, refer to them by their words, never "question 2" or "Later step 6".
- Write for reading in Obsidian, on a phone as well as a desktop. Status → Now is a callout that says whose move it is: `> [!todo] Your move` when you wait on me, else `> [!info] Working`, with the recap on the `> ` lines below. Every item in Immediate actions and Later is a plain bullet marked `- Yours: …` or `- Mine: …`, and I answer one with `>>`. A checkbox, `- [ ] Yours: …`, is only for a bare yes/no item: my tick on it is a yes, and `desk check` lists it (without the script, look for `- [x]` lines in Status), so handle it at your next turn as you would an answer. In log entries, use:
  - a table for a comparison or a set of results, at most three short columns, since wider ones scroll sideways on a phone;
  - `==highlight==` on the one thing an entry needs from me, at most one per entry. The same ask goes in Status once, as a Yours item in Immediate actions, whether it's a question or a step. Now's Your move points to it in a few words ("two Yours items below") and doesn't repeat it;
  - a `> [!warning]` callout for a risk, a blocker or a surprise I should know about;
  - a folded `> [!example]-` callout for evidence (output, counts, what you checked), so the entry reads short and the proof is one tap away;
  - a Mermaid `flowchart` when the big picture, a flow or its branches are clearer drawn than told; keep it to about a dozen nodes.
- Update Status as you go, whenever part of it changes: a step finishes, a decision lands, the plan changes, a question comes up. During long work, don't go more than about ten tool calls without touching it; if I installed the nudge hook (`~/.claude/hooks/desk-nudge.sh`), it reminds you when you do.
- When you rewrite Status, keep every answer of mine in it you haven't answered yet, including one after `>>` at the end of a line.
- Write the file only with the Edit or Write tool, never through Bash (`cat >>`, `sed`, inline python): a Bash write needs my approval, and the prompt drags the VS Code panel to the bottom. The one exception is `desk new`, which writes only a new file. Get the time from `desk check <file>` (below), or from `date` without the script, before writing a heading or the Status line; never guess it and fix it afterwards.
- A desk holds working notes only: never write keys, tokens, passwords or connection strings into it, nor query result rows or customer details (names, emails, phone numbers, addresses); give counts and table names instead, and say where the rows live. If I installed the nudge hook, it also refuses a desk write that looks like a key or holds an email address; it can't recognise query rows or names, so those rest on this rule.
- Inside a desk, link only what Obsidian can open: another desk as a wikilink with its month, `[[<YYYY-MM>/<file name>]]`, since a day-only name repeats from month to month, and a web page by its URL. Give a local file outside the vault as a path in backticks, never a link: a click on one makes Obsidian create an empty note at that path inside the vault.
- In chat, write one line: the gist, with a direct link on each item it names (a posted comment, a thread, a PR, a CI run), plus a VS Code line link to the new entry's `###` heading, `[entry <n>](<the file's absolute path>#L<line>)`. Take the line number (`desk line <file> <n>`, if I installed the script) after the turn's last edit to the file, since Status edits shift it. `open -a` can't open the desk at a section.
- Ask questions in the file, not with AskUserQuestion; its prompt drags the VS Code panel to the bottom.
- A question I send while you're working gets a one-line answer in chat at once, between tool calls, and the work carries on; the answer also goes in the next log entry. If answering takes research, give it to a background agent, keep working, and answer when it reports.
- My inline answers start with `>>`, either on their own line or at the end of the line I'm answering: `- >> yes` under a bullet, or `- Push it? >> yes` on the same line. Only `>>` marks an answer; a line that starts with a single `>` is a callout. Write `>` lines only as callouts, never a plain blockquote, and write `>>` yourself only inside backticks. At the start of each turn, if I installed `desk` at `~/.claude/bin/desk`, run `~/.claude/bin/desk check <file>` as one call, never chained with other commands; it prints the time, my open answers (the grep below, unchanged) and Status's line numbers. Else run the grep below. The grep returns only answer lines with no ` ✓` tag, anywhere in the file, old entries included; never filter or trim its output, and read every hit plus Status. When an entry handles my answer, append ` ✓§<n>` (that entry) to the end of my line wherever it is, and to each line of a multi-line answer. An answer on a Status line needs no tag; the rewrite that handles it drops the line. In your own text, write `>>` only inside backticks and leave it out of quotes of my words, so your lines never show up as open. Treat answers you haven't handled as part of my message, which may be just `>>`. When you wait on me (a run to finish, a step to take), ask me to send `>>`, never "r". In the new log entry, quote a few words of each answer you handle.
- Keep context clean: once a session has run about 15 of my turns, reached about 400k tokens of context, or had its context compacted, ask me at the next natural break (work pushed, no agent running, nothing half-done) whether to continue in a fresh session; a Handoff written before I'm ready to switch goes stale and adds noise. If I installed the nudge hook, it also reminds you, and shows me a line, when a session crosses 15 turns or 400k tokens. Only once I agree, add a log entry titled "Handoff": where things stand, what we tried and what surprised us (each with its evidence), uncommitted or unpushed work, running agents, open questions and any answer of mine still unhandled, my pending steps, anything from earlier entries the next session still needs, and the first next step. When the desk has passed about 2,000 lines, the Handoff starts a fresh desk instead: a new file for the same work, dated today, whose §1 is the Handoff, with a short recap, a link to the old desk and "old §<n>" for its entries; the old desk ends with a one-line entry linking the new file, and the resume line names the new file. The Handoff entry opens with the resume line, in backticks so I can copy it into the fresh session, naming that entry since a long desk can hold more than one: `Resume from the live desk ~/claude-replies/<YYYY-MM>/<file>, handoff §<n>`. Put the same line in Status → Now, and make it that turn's chat line, in backticks, with the entry link. Once a new session has picked the file up, the old session stops writing to it; until then, if I keep talking to the old session, it keeps the file and its Handoff current. The new session reads Status, the named Handoff and everything after it (`desk line <file> <n>` or `grep -n '^### @<n> '` finds its line), and the lines around each open answer; it opens an older entry only when one of those points to it. It shows the desk with `desk open` (if I installed the script), checks `git status` and `git log` before trusting what it says, continues its log numbering, and still runs the repo's own handoff, if the repo has one.

Find my open answers with:

```bash
grep -nE '(^|[^`])>>[^✓]*$' <file>
```
